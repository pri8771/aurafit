# Waiver — physical-device QA gates for the 1.0 (3) App Store submission

- **Date:** 2026-08-18
- **Approver:** owner (Priyansh Chordia); decision relayed and executed by the owner's assistant
- **Scope:** the App Store submission of AuraFit version 1.0, build `1.0 (3)`, made on
  2026-08-18 only. Not a standing waiver.

## Rules / gates waived

`docs/RELEASE_CHECKLIST.md` `TF-G1` items that require a physical iPhone, and their task plans in
`docs/testflight/tasks/`:

1. `AURA-OPS-012A` on-device half — signed Release build installs and launches on a physical
   supported iPhone (the archive half is done: the same archive was uploaded and processed).
2. `AURA-QA-002` — camera / import / export / persistence / permission device matrix.
3. `AURA-QA-004` — Dynamic Type, appearance, and supported-layout matrix (VoiceOver is separately
   **deferred**, not waived, per `docs/DECISIONS.md` DEC-005).
4. `AURA-QA-005` — performance / interruption / storage / thermal smoke.

Also not run before submission and covered by the same owner decision: `AURA-QA-006` internal
TestFlight smoke (the version was submitted directly for App Review).

## Affected feature

The whole 1.0 (3) product (scan, analysis, tips, scorecard export, history, settings) as
submitted to App Review.

## Reason

No physical device pass was available before the owner's chosen submission date. The owner
decided to submit 1.0 on the existing simulator and static evidence rather than hold the
submission.

## Replacement verification relied on

- Full suite 94/94 (iPhone 17 Pro simulator, iOS 26.4.1) and `RELEASE_CANDIDATE_GATE=PASS`
  on 2026-08-18 (`quality/evidence/release/1.0-3-full-free/README.md`).
- IPA/archive inspection (bundle identity, privacy manifest, no StoreKit link, no tier strings,
  entitlements, signing) recorded in the same file.
- Simulator UI-smoke test and the simulator screenshots in `quality/store-assets/1.0-3/`.

None of this is device evidence; the waived gates stay **open and unsatisfied** in
`docs/RELEASE_CHECKLIST.md` and `docs/TESTFLIGHT_READINESS.md`.

## Expiration / review

Expires with the 1.0 (3) submission. Any subsequent build (a 1.0 resubmission after an App Review
rejection, or any later version) must either execute these gates with dated evidence under
`quality/evidence/testflight/<TASK-ID>/` or obtain a new explicit owner waiver.
